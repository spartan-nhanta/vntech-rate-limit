What rate limiting is

Count requests per client. Once a client is over its limit, reject the rest with 429.

# rule: 100 requests / minute / per user

12:00:05  user_A  request #1    → 200 OK
12:00:05  user_A  request #2    → 200 OK
          ...
12:00:41  user_A  request #100  → 200 OK
12:00:42  user_A  request #101  → 429 Too Many Requests
12:00:42  user_B  request #1    → 200 OK   # own counter

12:01:00  # new minute, user_A's counter resets
12:01:02  user_A  request #1    → 200 OK
  • key Who gets counted: user ID, API key, or IP address.
  • limit How many requests are allowed.
  • window Over how long: per second, per minute, per day.
  • The bad client now hits its own limit. user_B and everyone else keep getting 200, and the server stays healthy.

  • In HTTP APIs the words are used interchangeably. AWS API Gateway calls its 429 "throttling"; GitHub and Stripe call it "rate limiting". Both reject, neither delays.

Throttling in an async system

A worker that slows itself down instead of rejecting

  • The SMS provider accepts 10 messages per second. The topic has 50,000 waiting.
  • Before each send, the worker asks the shared limiter for a token. No token → it sleeps and asks again.
  • No message is dropped and nobody sees a 429. The backlog drains at a steady 10/s and takes about 83 minutes.
  • The limiter lives in Redis so that adding a second worker doesn't double the send rate.

What the server sends back

The status code tells the client whether to retry. The headers tell it when.

429 Too Many Requests   # you sent too much
503 Service Unavailable # server is overloaded
403 Forbidden           # not allowed at all

HTTP/1.1 429 Too Many Requests
Retry-After: 30                # seconds to wait
X-RateLimit-Limit: 100         # your limit
X-RateLimit-Remaining: 0       # left in this window
X-RateLimit-Reset: 1704067320  # unix time of reset
  • 429 Slow down. Wait Retry-After seconds, then retry.
  • 503 Not your fault. Retry with backoff; the server may need minutes to recover.
  • 403 Don't retry. Waiting won't change the answer — fix the credentials or permissions.
  • Send X-RateLimit-Remaining on successful responses too, so well-behaved clients can slow down before they ever get a 429.
