2.1 · Client-side

Don't send the wasted request in the first place

Debounce
Call search when the user stops typing

Only the last keystroke, after 300 ms of silence, hits /search.

Batching
Buffer analytics events, flush every 5 s

Don't send one request per click or page view. Send the buffer as one POST.

Backoff + full jitter
On 429, wait Retry-After plus a random delay

Never retry earlier than the server asks. The random part spreads clients apart.

10 / 52client-side · debounce, batch, backoff
Why jitter matters

1,000 clients, no jitter, waking in unison

Jitter = a random part of the wait. Equal: half random, t/2 + random(0, t/2). Full: all random, random(0, t).

2.2 · Infrastructure · hop ① AWS WAF

Block any IP that sends more than 2,000 requests in 5 minutes

# aws_wafv2_web_acl, attached to CloudFront or the ALB
rule {
  name     = "per-ip-2000-per-5min"
  priority = 1
  statement {
    rate_based_statement {
      limit                 = 2000
      evaluation_window_sec = 300
      aggregate_key_type    = "IP"
    }
  }
  action {
    block {
      custom_response { response_code = 429 }
    }
  }
}
  • The flood stops at the AWS edge. It never opens a connection to the ALB, the ingress, or a pod.
  • Windows are 1, 2, 5 or 10 minutes. Good for floods and password guessing. Too coarse for "10 req/s".
  • Key can be IP, the X-Forwarded-For IP, a header like x-api-key, a path, or a mix.
  • Default block is 403. Return 429 so clients back off instead of treating it as an auth error.

2.2 · Infrastructure · hop ② ingress controller

Allow 5 login attempts per second per IP, before the request reaches a pod

# KongPlugin, attached to the /login Ingress
apiVersion: configuration.konghq.com/v1
kind: KongPlugin
metadata:
  name: login-rate-limit
plugin: rate-limiting
config:
  second: 5
  limit_by: ip
  policy: redis
  redis:
    host: redis.default.svc
    port: 6379
---
# on the Ingress for /login
metadata:
  annotations:
    konghq.com/plugins: login-rate-limit
  • 5 requests per second per client IP on /login. Request #6 in the same second gets 429.
  • The counter lives in Redis. 3 Kong pods share one count, so the limit stays 5, not 15.
  • It is a fixed window: the count resets every second. Section 4 shows what that allows at the edge.
  • Behind the ALB, trust X-Forwarded-For (trusted_ips, real_ip_header). Otherwise every user has the ALB's IP and shares one counter.

2.3 · Application / middleware

Where business context lives that infrastructure can't see

val tier = userService.getTier(userId)
// free / pro / enterprise

val limit = when (tier) {
  "enterprise" -> 10_000
  "pro"        -> 1_000
  else         -> 100      // free
}

val result = rateLimiter.check(
  key = "$userId:$endpoint", limit = limit)
  • Tier-based limits — a VIP or paying customer gets a materially higher budget than a free account.
  • Per-endpoint limits — a slow /export gets its own, tighter budget than a cheap read.
  • Per-API-key, not per-IP — many users legitimately share one office IP; a key identifies the actual user.
