This button calls a simulated GET /api/next-phone-number guarded by the same token bucket from the lecture — capacity 5, refill 1/second. Open this page in a few more tabs, mash the button in each, and watch them all draw from the same bucket through localStorage, exactly like replicas behind a load balancer sharing one Redis-backed limiter.

Switch to Per-tab bucket and open three or four tabs: each one now gets its own full 5-token bucket, so four tabs together sustain four times the intended rate — the exact "in-process memory ⇒ limit × replica count" problem from the lecture. Switch back to Shared bucket and the total across every open tab stays capped at 5, refilling at 1/s, no matter how many tabs you throw at it.

Fair warning: the shared bucket's read-modify-write against localStorage isn't atomic across tabs — the same non-atomic race as slide 12. Click fast enough in enough tabs and you may occasionally see one extra request slip through. That's not a bug in this demo; it's the bug the lecture is about.
